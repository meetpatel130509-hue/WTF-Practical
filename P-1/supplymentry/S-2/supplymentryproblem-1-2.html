Many hands.
One codebase.

When developers work on different parts of the same webpage, Git keeps every change traceable, shareable, and recoverable.

01 / The everyday loop

Git gives each developer room to work.

Each developer works on a separate branch. Git records snapshots, so changes can be reviewed and combined without overwriting the shared main branch.

01

Branch

Start an isolated line of work from main.

02

Commit

Save a focused snapshot with a message describing the change.

03

Merge

Bring a completed branch back into the shared branch.

04

Review

Use a pull request to discuss and approve changes before merging.

# Developer A updates the navigation
git switch -c feature/navigation
git add index.html   git commit -m "Update navigation links"
git push -u origin feature/navigation
02 / When lines overlap

Conflicts are a conversation.

Git can merge independent edits automatically. A conflict only appears when two branches change the same lines in incompatible ways. Nothing is lost: Git pauses and shows both versions.

03 / The shared habits

Good collaboration is designed.

Git is the record-keeper. A team’s conventions make that record useful to everyone.

Small commits

Keep each commit focused, so reviewers can understand it and roll it back safely.

Pull requests

Discuss code in context and catch integration problems before they reach production.

Pull often

Sync with main regularly to discover conflicts while changes are still fresh.

The short version: branches isolate work, commits preserve history, and merges bring ideas together. A conflict is simply Git asking the humans to choose.
